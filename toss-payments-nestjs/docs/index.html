01 · BOOTSTRAP

원본 요청 바이트를 먼저 보존합니다.

main.ts
import { NestFactory } from '@nestjs/core';
import { AppModule } from './app.module';

async function bootstrap() {
  const app = await NestFactory.create(AppModule, {
    rawBody: true,
  });
  await app.listen(process.env.PORT ?? 3000);
}

void bootstrap();

웹훅 경로 앞에 별도 JSON body 미들웨어를 붙이지 마세요. 파싱 뒤에는 서명 검증에 필요한 원본 바이트를 복구할 수 없습니다.

02 · COMPOSE

기존 주문 저장소를 DI로 배선합니다.

app.module.ts
import { Module } from '@nestjs/common';
import { orThrow } from '@gj-kit/toss-payments';
import {
  defineTossPaymentsConfig,
  parseApiSecretKey,
} from '@gj-kit/toss-payments/server';
import { TossPaymentsModule } from '@gj-kit/toss-payments-nestjs';
import { TossOrderStore } from './toss-order.store';

@Module({
  imports: [
    TossPaymentsModule.forRootAsync({
      inject: [TossOrderStore],
      useFactory: (orders: TossOrderStore) =>
        defineTossPaymentsConfig({
          secretKey: orThrow(parseApiSecretKey(process.env.TOSS_SECRET_KEY!)),
          orders,
        }),
    }),
  ],
  providers: [TossOrderStore],
})
export class AppModule {}

TossOrderStore는 앱의 DB provider를 감싼 OrderStore 구현입니다. 메모리 저장소는 결제 서비스의 금액 기준으로 사용하면 안 됩니다.

03 · HANDLE WEBHOOK

컨트롤러는 rawBody 경계를 넘기기만 합니다.

toNestWebhookHandler(toss.webhook, handlers)에 요청과 응답을 위임하면 검증·dedupe·핸들러 디스패치가 같은 경로로 실행됩니다.

  1. @InjectTossPayments()로 앱의 AppToss 타입을 주입합니다.
  2. @Post('toss')에서 req.rawBody를 받는 핸들러를 연결합니다.
  3. 핸들러는 검증된 이벤트만 이행하고, 미검증 상태 변경은 재조회 결과만 반영합니다.
