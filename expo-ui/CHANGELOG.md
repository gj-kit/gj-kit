## 0.8.0

### Minor Changes

- 7a2c809: Add three data-display components and extend the existing contracts of SegmentedControl, Text, DataTable, Badge, Section, Accordion, Chip, Dialog/ConfirmDialog, Skeleton, EmptyState, and Card for detail panes, dashboards, filter rows, admin headers, and reduced-motion honesty. Everything is additive; the only behavior change to existing props is that modal animation now honors the platform reduced-motion preference.

  - **`KeyValueList`** (new): a themed description list of `{ label, value }` rows. The web build emits a real `<dl>` with `<dt>`/`<dd>` pairs (grouped in `<div>`s as HTML allows); native uses honest `list`/`listitem` roles and folds scalar pairs into one "label: value" accessibility element while leaving custom-node values reachable. `layout` (`inline` | `stacked`), `size` (`sm` | `md`), `divider`, per-layer `style`/`className` hooks, and an optional `accessibilityLabel`. On the web the inline label-column sizing (the built-in width plus any `width`/`minWidth`/`maxWidth`/flex sizing from `labelStyle`) is carried by the block-level `<dt>` — React Native Web text is `display: inline`, so a width on the text node alone would be ignored and values would not align. An empty `items` renders nothing. `null`/`undefined`/boolean values are compile errors (and runtime config errors).
  - **`StatGrid`** + **`StatItem`** (new): one bordered N-column metric grid. `columns` must be an integer ≥ 1 (runtime config error otherwise). Each cell is a group named "label, value[, hint]"; a `ratio` renders a thin bar through the `ProgressBar` contract with the value clamped to [0, 1] and exposed as a 0–100 `aria-valuenow`. `tone` (`neutral` | `info` | `success` | `warning` | `danger`) tints the value and bar — thresholds stay with the caller. Values render with tabular numerals.
  - **`Toolbar`** (new): a named wrapping row of controls (`role="toolbar"` + required `accessibilityLabel`). `wrap`, `gap` (spacing token key), `align` (`start` | `center` | `end` | `space-between`), and `bordered`. Children keep their own focus; the library deliberately adds no arrow-key roving tabindex.
  - **`SegmentedControl`** gains `variant?: 'filled' | 'underline'`. `filled` (default) is pixel-identical to the previous look. `underline` draws a transparent track with a hairline, a `colors.tabActive` underline and label on the selected segment, and `colors.tabInactive` on the rest — the same token roles as `Tabs variant="underline"`, which it visually matches (same `md` height and `typography.tab`) for filter rows that change a list rather than swap panels. Radio semantics, roving focus, and keyboard behavior are unchanged.
  - **`Text`** gains `tabularNums?: boolean`, emitting `fontVariant: ['tabular-nums']` (React Native Web serializes it as the CSS `font-variant` shorthand) so columns of figures align.
  - **`DataTable`** gains `onRowPress?: (row, { rowKey, rowIndex, presentation, originalEvent }) => void` and `getRowAccessibilityLabel?: (row) => string` (typed to require a definitely present `onRowPress`; the default name joins cells as "header: value"; the absent branch accepts an explicit `undefined` so `onRowPress={canOpen ? open : undefined}` compiles). Consumer row content is never nested inside a button, on any presentation. On the web the table body row stays a real focusable `<tr role="row" tabIndex={0}>` and the compact list row a focusable `listitem`; both activate on click, Enter, and Space, ignore clicks that start on interactive descendants (selection checkboxes, links, sort controls keep working), only honor keys when the row itself is focused, and reference a visually hidden keyboard hint via `aria-describedby`. The hint text comes from the new `UiStrings.rowActivationHint` key (en "Press Enter or Space to activate" / ko provided) — hand-assembled `UiStrings` bundles must add it, which is the documented complete-object evolution path. Native table/list presentations split touch and assistive tech: a non-accessible `Pressable` surface takes pointer presses (nested touchables inside cells still win their own touches) while a sibling one-point button carries the accessible row name and activation, so iOS VoiceOver no longer collapses the row into one button that hides descendant controls; the selection checkbox stays outside both. A new `DataTableRowPressContext` type is exported. The web table's sizing contract (`table-layout: fixed`, `width: 100%`, scroll region with `overflow-x: auto`, `minTableWidth` gate) is now pinned by a unit test; no sizing bug was found.
  - **`Badge`** gains `accessibilityLabel?: string` — overrides the accessible name derived from the visible label (e.g. keep the visible label localized while the name carries the raw status code, "결제 완료 (PAID)"). When present, the badge is exposed as one accessibility element with that name on both platforms: native flattens the accessible root, and the web root takes `role="img"` with the visible label and icon hidden from assistive technology, because an aria-label on a role-less generic element is ARIA-prohibited naming that web screen readers ignore (the readonly-Rating pattern). Absent means zero change.
  - **`Section`** gains `headingLevel?: 1 | 2 | 3 | 4 | 5 | 6` (title becomes a real heading — native `accessibilityRole="header"`, web `role="heading"` + `aria-level`), `titleStyle`/`titleClassName`, `count?: number` (a token-styled count pill next to the title: `surfaceSubtle` pill, `textMuted` caption; must be finite — runtime config error otherwise), `countAccessibilityLabel` (names the pill for assistive tech, e.g. "40 of 812" — carried by the numeral text element on native and by `role="img"` + aria-label on the pill with the numeral hidden on the web, where naming a role-less generic element is ARIA-prohibited), and `accessory?: ReactNode` after the count. With none of the new props the render tree is byte-identical to before.
  - **`AccordionItem`** gains `trailing?: ReactNode` — a presentation-only slot in the header row between the title copy and the expansion indicator (count pills etc.). The trigger's accessible name stays the title and the slot is hidden from the accessibility tree; interactive trailing content is unsupported, and information that matters to assistive technology belongs in `description`.
  - **`Chip`** gains `count?: number` (rendered after the label in `textMuted` — `textSubtle` when disabled — and joined into the accessible name of the interactive kinds as "완료, 700"; static chips stay ordinary readable text; non-finite counts are runtime config errors) and `trailing?: ReactNode` (presentation-only, hidden from accessibility; a trailing action belongs to the removable kind's dedicated button).
  - **Reduced motion**: `Dialog` motion is now opt-in by platform consent — the same conservative policy Sheet already had. The modal animates only after `AccessibilityInfo.isReduceMotionEnabled()` affirmatively resolves false, and presents with `animationType 'none'` regardless of the prop both while the preference is still unresolved (the async startup window, so a dialog mounted already-visible never plays an entrance for reduce-motion users) and whenever reduced motion is on. A preference that resolves while the dialog is open never replays the in-flight entrance; the new animation commits on the next closed state (Sheet's latch). Everything composing Dialog (`ConfirmDialog`, `ActionSheet`, `Sheet`, `Popover`) inherits it. `ConfirmDialog` gains an `animationType?: 'none' | 'fade' | 'slide'` passthrough. README documents the web-jest consequence: until the preference resolves false, Dialog presents with 'none', so `role="dialog"` appears without the `animationend` event jsdom never fires.
  - **`Skeleton`** now drives its pulse with the JS animation driver on web (`useNativeDriver: Platform.OS !== 'web'`), eliminating RNW's per-instance "useNativeDriver is not supported" console warning; the pulse itself is unchanged on every platform.
  - **`EmptyState`** gains `variant?: 'default' | 'compact'` (new exported `EmptyStateVariant`). `compact` is a one-line notice for table-internal/inline empty rows: label-role title, `spacing.lg` padding, `spacing.xs` gap, and no built-in icon — `leading` renders bare and only when explicitly provided. Absent variant is pixel-identical to before.
  - **`Card`** gains a pressable/selectable form (new exported `StaticCardProps`/`PressableCardProps` union). `onPress` turns the card into an honest button and makes an explicit `accessibilityLabel` a compile-time requirement (rich children never derive a name; blank strings are runtime config errors). Providing `selected: boolean` exposes the card as an independent toggle button — web `aria-pressed`, native togglebutton + checked — with `primarySoft` background and `primary` border while selected. Card deliberately does not fake radio semantics: `RadioGroup` remains the honest widget for exactly-one-of-N groups, and the README documents that a selectable-Card group reads as independent toggles. The static form is unchanged and still rejects `onPress`/`selected`/`disabled` at compile time.
  - **`DialogPanel`** gains `headerStyle` (the header row wrapping leading, the title/description copy, and the close button), `descriptionStyle`, `closeButtonStyle`, `closeIcon` (replaces the default ×/`icons.close` mark — static node or `RenderIcon` — while the button's accessible name stays `closeAccessibilityLabel ?? strings.close`; per the library-wide icon-slot convention a null, passed directly or returned from the `RenderIcon`, falls back to the default mark — an empty fragment is the escape for a mark-less button), and `hideHeader`. `hideHeader` skips the visible title/description block and the `leading` node but keeps the close-button row; because hiding the visible title removes the dialog's derived accessible name, a modal Dialog whose direct panel sets `hideHeader` now requires the Dialog `accessibilityLabel` (clear render-time error otherwise — the same naming discipline as the arbitrary-content branch), and the `aria-describedby` relationship is dropped along with the unrendered description node. A defined `hideHeader` must be an actual boolean (runtime TypeError otherwise), so JS consumers cannot slip a truthy non-boolean past the naming enforcement.
  - **`Dialog`** gains `backdropStyle` — a style override layered onto the backdrop pressable after the theme's `colors.overlay` (modal presentation only; inline renders no backdrop). Overriding the background color (e.g. `transparent` for dim-less anchored overlays, or a pixel-spec dim) shifts scrim-contrast responsibility to the consumer; the README says so loudly.
  - **`ConfirmActionRow`** gains per-button escape hatches: `cancelTestID`/`confirmTestID`, `cancelStyle`/`confirmStyle` (button containers, layered after the built-in flex sizing), and `cancelLabelStyle`/`confirmLabelStyle`.
  - **`ConfirmDialog`** gains `cancelTestID`/`confirmTestID` passthrough for its internal buttons, overriding the derived `${testID}-cancel`/`${testID}-confirm` defaults (which are unchanged when the new props are absent).
  - **`Sheet`** gains `showCloseButton` (default true). The close X is a convenience, not the only exit — with `showCloseButton={false}` the backdrop, Escape, hardware Back, and the accessibility escape still dismiss. Combining it with `dismissDisabled` removes every built-in exit: the sheet stays open until the caller closes it, so the caller owns providing an explicit way out (typically footer actions) — the forced-choice confirm-sheet pattern, documented loudly in the README.
  - **`Menu<T>`/`Select<T>`** gain `triggerTestID` (testID on the actual trigger pressable — the consumer's `fireEvent.press` contract; on the web Select it replaces the derived `${testID}-trigger`), plus `triggerHoverStyle`/`itemHoverStyle` — pointer-hover style hooks layered after `triggerStyle`/`itemStyle`, tracked only when the prop is provided, never applied to disabled targets, and inert on touch platforms. Stale hover highlight is cleared when the overlay closes.
  - **Menu/Select OverlayProvider absence**: the throw stays (graceful degradation was rejected — outside-press/Escape ownership is arbitrated by the overlay stack's topmost decision, which cannot be preserved without a stack), but the error message now names the guarantee and the exact fix: wrap the app or test render in `<UiProvider>` (which creates the overlay scope automatically) or an explicit `<OverlayProvider>`.

- 004616f: Round E admin-console follow-ups. Everything is additive; absent props render byte-identical trees.

  - **`DataTable`** gains `activeRow?: { key: RowKey | null; style?: StyleProp<ViewStyle> }` — an app-driven "current row" highlight for consoles where activating a row opens a detail surface (Sheet, side panel) that stays in sync with the table. The default visual is token-driven: a `colors.primarySoft` full-row wash (selection checkbox cell included) plus a `colors.primary` start-edge accent bar, drawn absolutely so it never shifts content and never collides with `showColumnBorders` — on the row-header cell in table presentations and on the row container in list presentations. While the default accent shows, the active list row also clips it to its rounded corners (`overflow: hidden` on that row only), so the bar never paints outside the `radius.sm` silhouette or the `variant="outline"` hairline; table-cell accents stay square and rows without the default accent render exactly as before. This is deliberately not selection: the row is never `aria-selected` (that would claim grid/listbox semantics this static table does not have); instead the active web `<tr>` (table presentation) and listitem (list presentation) carry `aria-current="true"`, valid on any element. Native presentations are visual-only — no accessibility state is faked, so the detail surface itself (its Sheet title, for example) must convey which record is open; the active native row exposes a `${testID}-row-${rowKey}-active-accent` testID for consumer specs. `activeRow.style` replaces the default wash and accent entirely (`aria-current` stays). Key and style are grouped in one object, the same shape discipline as `selection`: a style without a key is impossible by construction, and the grouping adds no new discriminated-union factor — a flat `activeRowKey`/`activeRowStyle` pair typed as a paired union was measured to push the existing 24-member `DataTableProps` union product past TypeScript's intersection-of-unions normalization limit, breaking source compatibility for consumers that spread `DataTableProps`.
  - **`DataTable`** also gains `rowStyle?: (row, { rowKey, rowIndex, active, presentation }) => StyleProp<ViewStyle> | undefined` — a general per-row style hook layered after every built-in row visual (stripes, the active wash, `activeRow.style`), applied to table rows and list rows on both platforms; returning `undefined` leaves a row unchanged. On the web table presentation the result is applied to each of the row's cells, because a real `<table>` row box cannot paint above its opaque cells. It composes independently with `onRowPress`, selection checkboxes, `striped`, and `showColumnBorders`. A new `DataTableRowStyleContext` type and the `DataTableActiveRow` shape are exported. Internal fix surfaced by the hook's contract: the native component previously built the visual-table tree even in list presentation, which would have invoked `rowStyle` with a phantom `presentation: "table"` context — the tree is now constructed only for the presentation actually shown.

- 004616f: Round E mobile follow-ups for `Menu<T>`/`Select<T>`: an app-owned trigger slot and a native anchored presentation (owner-approved revision of design doc §11's arbitrary-anchor deferral, 2026-08-24). Everything is additive; absent props render byte-identical trees — the owned trigger and the bottom/center sheets are untouched by default.

  - **`renderTrigger?: (trigger: TriggerRenderProps) => ReactElement`** on Menu and Select, web and native. The kit injects everything behavior and accessibility own — `ref`, `onPress`, `disabled`, role (`button` for Menu and native Select, `combobox` for web Select), `accessibilityLabel`, `accessibilityState`/`aria-expanded` (dual-written: RN maps aria-\* to native state, RNW needs the DOM attribute), Select's `accessibilityValue` text and `accessibilityHint`, web `aria-haspopup`/`aria-controls` ids plus the keyboard/blur handlers, `testID` (from `triggerTestID`; web Select falls back to the derived `${testID}-trigger`), and the `onLayout` re-measure hook anchoring needs — while the consumer owns only the visuals. The injected object carries platform wiring beyond the declared `TriggerRenderProps` keys (exported), so the contract is: spread the whole object onto one Pressable — or an equivalent host that actually forwards RN press handling; a plain View silently drops `onPress` and is not a valid host. The web trigger's Enter/Space/Arrow open path is owned by the injected key handlers (with the Pressable keyboard-press duplicate suppressed), so keyboard activation does not depend on the host's role=button emulation. Misuse enforcement is two-tier: opening without the injected `ref` attached throws on both platforms (an effect on the open transition), and on web the same effect additionally verifies that the injected wiring — role, `aria-expanded`, an accessible name — actually landed on the attached DOM node, so a partial spread or a ref parked on a wrapper also throws instead of silently shipping a focusable trigger that announces nothing. Native cannot introspect RN host props at runtime, so ref attachment is its enforcement ceiling — passing the same renderTrigger through a web render (tests count) catches native-only partial spreads. Owned trigger-visual props (`variant`/`size`/`triggerStyle`/`triggerHoverStyle`/`triggerLabelStyle`/`iconOnly`/`triggerIcon` on Menu; `size`/`leading`/`triggerStyle`/`triggerHoverStyle`/`valueStyle` on Select) are rejected both at compile time (props union) and at render (`TypeError`) while `renderTrigger` is present. Select keeps rendering the label row and helper/error text outside the trigger.
  - **Native `presentation: "anchored"`** renders the item panel dim-less inside a transparent Modal, positioned by the measured trigger frame (`measureInWindow`) with the same `placement`/`sideOffset`/`alignOffset`/`collisionPadding` vocabulary as the web popup — flip/shift/clamp share the web's geometry through a new pure `computeAnchoredPanelFrame` (internal), and an over-tall panel is capped to the resolved collision space and scrolls internally. The backdrop paints nothing but still owns every outside gesture, so an outside tap — including an attempted scroll of the content underneath — dismisses the panel (dismiss-on-scroll, not reposition, is the documented policy; content under a full-window Modal cannot scroll while it is open). Escape, hardware Back, and the accessibility escape dismiss exactly like the sheets; the sheet's cancel action is intentionally absent from this popover-shaped surface. A re-measured trigger that leaves the collision boundary closes the panel with reason `'anchor-detached'`, matching the web popup (and, like the web, `dismissDisabled` also vetoes that cleanup — the panel stays clamped). On Android the anchored Modal draws with translucent status/navigation bars so its window shares the coordinate origin `measureInWindow` reports; the `statusBarTranslucent`/`navigationBarTranslucent` props behind this are new public `Dialog` props (Android modal presentation only, ignored elsewhere; real-device verification of the coordinate alignment is tracked as a design-doc §12 residual risk). `"auto"` still resolves to bottom/center exactly as before, `bottomInset`/`keyboardOverlap` remain sheet-only, and the web implementation (always anchored) ignores the prop.

- 004616f: Round E stage E3 — pure date components. No native-picker peer (owner decision): everything below is clock-free, time-zone-free keyboard/pointer UI plus pure math, and the JavaScript Date object appears in no public signature — a Date is an instant whose civil reading shifts with the runtime time zone, so date state travels as the new plain `CalendarDate` (`{ year, month(1-12), day }`). Everything is additive; runtime dependencies stay at zero.

  - **Pure calendar math** (new, root entry): `CalendarDate`/`CalendarMonth`/`CalendarWeekday`/`CalendarWeekStart` types plus `isCalendarLeapYear`, `daysInCalendarMonth`, `isValidCalendarDate` (a real-day guard — Feb 30 fails), `compareCalendarDates`/`isSameCalendarDate`/`isSameCalendarMonth`, `clampCalendarDate` (returns the same object when in range), `addCalendarDays`/`addCalendarMonths` (exact month/year boundary crossing via integer serial-day math, no Date), `calendarDayOfWeek` (0 = Sunday), ISO-key serialization `formatCalendarDateKey`/`parseCalendarDateKey` (strict zero-padded `"YYYY-MM-DD"`, the supported year space 1–9999), and `buildMonthGrid(year, month, weekStartsOn?)` → `MonthGrid` of 7-cell `MonthGridWeek` rows. The grid spans exactly the weeks the month needs (4–6 — no phantom sixth week); leading/trailing cells are real adjacent-month dates flagged `inMonth: false`. Every month of the year space lays out without throwing; the one documented caveat is the two edge months (January 0001, December 9999), whose padding cells name days outside 1–9999 (year 0 / 10000) — those padding dates fail `isValidCalendarDate` and are display data, not values to feed back into the calendar API. The module (`src/dates`) imports neither react nor react-native, so Node scripts and servers can load the math safely.
  - **`MonthCalendar`** (new): a controlled month grid where the application owns every piece of date state — the displayed `month`, the selected `value`, and even `today` (an optional prop; the kit never reads the clock, so omitting it just means no today ring and no `aria-current="date"`). Header copy comes from a required `labels` prop rather than UiStrings, because weekday abbreviations and the month title are locale/calendar formatting decisions and the title changes every month — `labels.weekdays` is always a Sunday-first 7-tuple and `weekStartsOn` (`0 | 1`, default 1 = Monday) only reorders the columns. `renderDay` replaces a day's CONTENT only; the cell itself (gridcell/button semantics, focus, press) stays kit-owned so a consumer slot can never drop accessibility, and it is also called for `inMonth: false` padding cells so apps can render dimmed adjacent-month days. Padding cells are non-interactive; on the web they REMAIN in the accessibility tree as nameless `aria-disabled` gridcells with only their content hidden — hiding the cell itself would break screen-reader column arithmetic (exposed cell position determines the weekday column, the APG date-picker choice) — while on native, where each day is an independent button and no column mapping exists, padding is hidden from the tree entirely. `minDate`/`maxDate` disable out-of-range days — still focusable (`aria-disabled`), activation ignored. Default day accessible name is the locale-free ISO key; `getDayAccessibilityLabel` localizes it. Web semantics: `role="grid"` (named by the required `accessibilityLabel`) > `row` > `columnheader`/`gridcell`, `aria-selected` on in-month cells whenever selection is exposed (`onValueChange` or `value` present), and a roving-tabindex keyboard whose implemented surface is exactly: arrows ±1/±7 days clamped to the displayed month (movement that would leave the month is ignored), Home/End to the week's first/last in-month day, PageUp/PageDown raising `onMonthChange` with the previous/next month and restoring focus to the same day number (clamped in shorter months; a silent no-op at the edges of the year space instead of a throw), Enter/Space to select. Without `onValueChange` the grid is a static presentation (no focus, no keyboard, no press). Native: each in-month day is an honest button carrying the full date label and selected/disabled state (dual `accessibilityState` + `aria-*` notation, the Tabs convention); the weekday header row is hidden from the accessibility tree as noise. The component ships no built-in previous/next buttons — apps compose their own (Toolbar + Button) and share the `month` state with the keyboard path; on native only those app buttons call `onMonthChange`. Escape hatches: `dayStyle(ctx)` layered after the built-in token visuals (primarySoft selected wash, primary today ring drawn on an always-present transparent border so layout never shifts), `titleStyle`/`weekdayStyle`, per-day `${testID}-day-YYYY-MM-DD` testIDs.
  - **`DateField`** (new): segmented year/month/day keyboard input, controlled `value: CalendarDate | null` ↔ `onValueChange`, order via `segmentOrder` (default ymd; a non-permutation is a runtime config error). The commit contract is deliberately narrow and tested verbatim: typing keeps LOCAL per-segment drafts and commits only the moment all three are complete (year 4 digits, month/day 2); the commit clamps month → 1-12, day → the real length of that month (Feb 31 → 28/29), result → `minDate`/`maxDate`, and calls `onValueChange` only when the result differs from `value`; emptying all three segments commits `null` (partially empty commits nothing); blur zero-pads a single-digit month/day but NEVER pads or century-guesses a short year (it stays an uncommitted draft), and blur with complete drafts drops them so the display snaps back to the controlled value; a parent `value` change discards drafts. Numeric keyboard on both platforms, unambiguous first digits complete early ("9" → "09" for months, "4"-"9" for days) with auto-advance, Backspace on an empty segment flows back, and web ArrowUp/ArrowDown steps within the segment's own range (day max uses the real month length when year+month are known) — an empty segment does not respond, because the kit is clock-free and has no "today" to seed from, and an incomplete year draft ("26") is equally inert: stepping never pads or century-guesses a short year, mirroring the blur contract. Semantics: web `role="group"` wired to the label plus per-segment `role="spinbutton"` with `aria-valuemin/max/now` — the day segment's `aria-valuemax` is computed with the same rule as the step ceiling (the real month length once year+month are known, 31 only while unknown) — and per-segment `aria-describedby`/`aria-errormessage` alongside `aria-invalid`, because ARIA only honors `aria-errormessage` on the invalid element itself (the segments are the focusable elements, matching TextField's wiring); native three inputs labeled "field label, segment name". Segment names come from three NEW `UiStrings` keys `dateFieldYear`/`dateFieldMonth`/`dateFieldDay` (en "Year"/"Month"/"Day", ko "년"/"월"/"일") — hand-assembled UiStrings bundles must add them, the documented complete-object evolution path — overridable per field via `segmentLabels`. `label`/`error`/`helperText` wiring matches TextField, and the `nativeID`/`aria-*` passthrough props make it compatible with the FormField render-prop contract. TimeField was considered and deliberately deferred out of this stage's budget.
  - Type contracts: `CalendarDate` is a closed flat shape (a `Date`, a key string, or an excess property is a compile error on both components' `value`), the `renderDay`/`getDayAccessibilityLabel`/`dayStyle` context is fully readonly, `weekStartsOn` admits only `0 | 1`, `labels.weekdays` is enforced as a 7-tuple, and `MonthGridWeek["length"]` is literally `7`.

The API requires exactly one of caption or accessibility label, a stable row key, an existing row-header column, and a nonblank scalar extractor for every column. Literal column tuples narrow controlled single-sort state to only `sortable: true` IDs, while consumers continue to own row ordering, filtering, pagination, fetching, and virtualization.

  DataTable also provides controlled include-only multiple checkbox selection. Visible-page select-all changes only selectable rows, preserves off-page keys, and reports only keys whose selected boolean actually changed. Loading, error, ready, and refreshing are mutually exclusive states; explicit list and adaptive presentations require an app-owned compact row renderer. Add `sortAscending`, `sortDescending`, and `sortUnsorted` to the complete `UiStrings` contract. Large editable or virtualized grids, column pinning/resizing, and composite grid keyboard navigation remain reserved for a separate future `DataGrid`.

  Add controlled `Pagination` as an independent navigation primitive rather than a `DataTable` footer. Numbered mode separates item totals (`totalItemCount` + `pageSize`) from precomputed page totals (`pageCount`), keeps the public page 1-based, and reports typed request reasons plus clamped item offsets. Cursor mode requires a visible status and previous/next capabilities without inventing a numeric position. Web renders a semantic `nav > ol > li > button` structure with one `aria-current="page"`; native exposes an honest toolbar and changes numbered `auto` from compact below the tablet breakpoint to full above it. Add deterministic boundary/sibling range generation and `previousPage` / `nextPage` to the complete `UiStrings` contract. Fetching, route synchronization, cursor storage, automatic page clamping, virtualization, and infinite-scroll triggers remain app-owned.

  Raise built-in text contrast to 4.5:1, preserve Card shadow and child clipping together, require an iOS-safe accessible name for required FormField controls, add native Link open-error handling, and use RTL-aware FAB and Slider direction. Slider exposes named adjustable thumbs and full web keyboard control; ToggleGroup exposes a named toolbar, pressed state, orientation-aware roving focus, and icon-only name enforcement. Toast keeps action and close as sibling controls, supports explicit live-announcement modes, and preserves visible lifetime across hover/focus/touch, native AppState, RNW page visibility, and browser window blur.

  Introduce conditional native/web root builds plus an internal stack, position, typeahead, presence, and scoped-host overlay kernel without adding direct runtime dependencies. The web condition imports the optional `react-native-web >= 0.21` peer directly, while native consumers continue to resolve `react-native` without installing React Native Web.

  Expose `OverlayProvider` as the shared Menu/Select/Popover/Tooltip environment and let the root `UiProvider` create it automatically; nested `UiProvider` instances reuse the outer scope, while explicit providers support provider-less or intentionally isolated overlays. Modal Dialog registers once in the optional stack, supplies its layer as the parent of descendant overlays, and routes backdrop, Escape, Back, accessibility escape, and close requests through the same topmost guard; inline Dialog remains outside the stack. The environment also coordinates web Tooltip warm-up and tears down pending timers on unmount. On web, Menu uses menuitem/menuitemcheckbox focus, Select keeps focus on a combobox with an active listbox option, Popover renders a bounded non-modal rich dialog, and Tooltip renders a delayed plain-text description. On native, Menu, Select, and Popover adapt to Dialog surfaces while Tooltip maps its description to the owned icon action's accessibility hint. Public Portal/Host and arbitrary `asChild` trigger composition remain intentionally unpublished. `Sheet` is deliberately an accessible edge-positioned modal rather than a simulated drag surface; snap points and pan gestures remain reserved for a future optional `BottomSheet` adapter backed by a platform-grade gesture implementation.
