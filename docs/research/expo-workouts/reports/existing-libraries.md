# Audit of existing React Native / Expo health libraries (HealthKit + Health Connect)

Researched 2026-08-22 against live npm registry, npm downloads API, GitHub REST API (authenticated `gh`), raw GitHub sources at each repo's default branch, React Native Directory API, Context7, and official Apple/Google/Expo docs. Every version/date below was read from a live source on this date; where a live source contradicted my prior knowledge the live source wins and is noted.

Confidence tags: `[official-doc]` vendor docs · `[source-code]` read from the repo/registry/API · `[secondary]` third-party page or README claim not independently verified · `[unverified]` inference, needs a check.

---

## 1. Facts

### 1.1 Ecosystem / platform level

1. There is **no official Expo health module**. The SDK 57 API reference lists Pedometer, Accelerometer, Gyroscope, Magnetometer, Barometer, LightSensor, DeviceMotion, Location, Sensors — nothing for HealthKit or Health Connect; `expo/expo/packages/` contains no package matching `health|fit|workout`. `[official-doc]` https://docs.expo.dev/versions/latest/ · `[source-code]` https://api.github.com/repos/expo/expo/contents/packages
2. `expo-health` on npm is an empty placeholder: single version `0.0.0` published 2021-08-13, no repository, no license, no description (307 downloads/week are noise). `expo-healthkit`, `@expo/health`, `expo-healthkit-sdk`, `@react-native-health/core`, `react-native-health-kit` do **not exist** on npm (registry returns `Not found`). `[source-code]` https://registry.npmjs.org/expo-health
3. Google Fit is being turned down: "The Google Fit APIs, including the Google Fit REST API, will be deprecated in 2026." and "As of May 1, 2024, developers cannot sign up to use these APIs." Google directs to the Health Connect migration guide. `[official-doc]` https://developers.google.com/fit
4. Google Play requires a Health Connect data-type access declaration in the **Play Console** (App content page). Apps that previously used the Google Form had to migrate by **January 22, 2025**. Published apps without approved declarations show users a "can't access Health Connect" dialog at link time. The page gives no special rule text for exercise routes or review duration. `[official-doc]` https://developer.android.com/health-and-fitness/guides/health-connect/publish/request-access — The react-native-health-connect README additionally claims the standalone Google Form "is being retired on September 3rd, 2026" and "Approval can take up to 7 days"; I did not find that on the official page. `[secondary]`
5. Weekly npm downloads (2026-08-13 → 2026-08-19): `@kingstinct/react-native-healthkit` **122,851**; `react-native-health-connect` **98,593**; `expo-health-connect` 40,846 (deprecated shim, lagging installs); `react-native-health` **39,285**; `react-native-google-fit` 2,983; `react-native-nitro-health` 435; `react-native-apple-healthkit` 267; `@mbdayo/react-native-health-kits` 230; `rn-apple-healthkit` 92; `@ovalmoney/react-native-fitness` 43; `@yzlin/expo-healthkit` 13; `react-native-healthkit` 3. 6. `react-native-nitro-modules` latest is **0.37.0** (2026-08-20), peer `react-native: *`. Kingstinct requires `>=0.35`. `[source-code]` https://registry.npmjs.org/react-native-nitro-modules

### 1.3 `react-native-health-connect` (matinzd) — Android only, TurboModule + old-arch fallback

17. npm latest **4.1.3 published 2026-08-06**; 46 versions; 2025:3, 2026:9 (3.5.2 → 4.1.3, with 4.0.0/4.1.0/4.1.1 all on 2026-08-01). `peerDependencies: { "@expo/config-plugins": ">= 6.0.2" (optional), "expo": "*" (optional), "react": "*", "react-native": "*" }`; `codegenConfig: { name: "RNHealthConnectSpec", type: "modules", jsSrcsDir: "src" }`; MIT. `[source-code]` https://registry.npmjs.org/react-native-health-connect
18. GitHub: 413 stars; **47 open issues** (+4 PRs), 128 closed; last commit **2026-08-06**; oldest open issue #73 dated 2024-03-14; contributors: matinzd 203 commits, next human 4 — **single-maintainer project**. `[source-code]` https://api.github.com/repos/matinzd/react-native-health-connect
19. **v4.0.0 (2026-08-01) bundled the Expo module**; `expo-health-connect` is deprecated on npm with the message "Merged into react-native-health-connect v4 — remove this package, replace the expo-health-connect entry in your app.json plugins array with react-native-health-connect, then re-run expo prebuild --clean". Leaving it installed fails the Android build with a duplicate `expo.modules.healthconnect.HealthConnectPackage` class. `[source-code]` https://api.github.com/repos/matinzd/react-native-health-connect/releases · https://registry.npmjs.org/expo-health-connect
20. **Tested on Expo SDK 57**: `example-expo/package.json` pins `expo ~57.0.9`, `react-native 0.86.2`, `react 19.2.3`, `expo-build-properties ~57.0.2`. Android dependency `androidx.health.connect:connect-client:1.1.0` (stable since 4.1.0); `minSdkVersion` must be 26; README recommends `compileSdkVersion 36 / targetSdkVersion 36`. `[source-code]` https://raw.githubusercontent.com/matinzd/react-native-health-connect/main/example-expo/package.json · `.../android/build.gradle`
21. Architecture selection is runtime: `const isTurboModuleEnabled = global.__turboModuleProxy != null` picks `NativeHealthConnect` (TurboModule, `TurboModuleRegistry.getEnforcing('HealthConnect')`) else `NativeModules.HealthConnect`; on iOS every call throws `Platform not supported. 22. Permission model: `requestPermission(permissions: (Permission | WriteExerciseRoutePermission | BackgroundAccessPermission | ReadHealthDataHistoryPermission)[]): Promise<...[]>` with `Permission = { accessType: 'read'|'write'; recordType: RecordType }`, `WriteExerciseRoutePermission = { accessType: 'write'; recordType: 'ExerciseRoute' }`, `BackgroundAccessPermission = { accessType: 'read'; recordType: 'BackgroundAccessPermission' }`. Manifest permissions are NOT added by the plugin; Expo users list them under `expo.android.permissions` (e.g. `android.permission.health.READ_EXERCISE`, `READ_EXERCISE_ROUTES`, `WRITE_EXERCISE`, `WRITE_EXERCISE_ROUTE`). The plugin only adds the `androidx.health.ACTION_SHOW_PERMISSIONS_RATIONALE` intent filter and the Android 14+ `ViewPermissionUsageActivity` alias. `[source-code]` https://raw.githubusercontent.com/matinzd/react-native-health-connect/main/src/types/index.ts · `.../app.plugin.js`
23. Route read model: `ExerciseSessionRecord.exerciseRoute?: { type?: ExerciseRouteResultType; route: Location[] }` with `enum ExerciseRouteResultType { DATA, NO_DATA, CONSENT_REQUIRED }` mapped from `ExerciseRouteResult.Data/NoData/ConsentRequired`; `Location = { time: string; latitude; longitude; horizontalAccuracy?: Length; verticalAccuracy?: Length; altitude?: Length }` where `Length = { value: number; unit: 'meters'|'kilometers'|'miles'|'inches'|'feet' }`. `requestExerciseRoute(recordId: string): Promise<Location[]>` launches `ExerciseRouteRequestContract` and rejects with `ExerciseRouteAccessDenied("Request to access exercise route denied")` on denial. `[source-code]` https://raw.githubusercontent.com/matinzd/react-native-health-connect/main/src/types/base.types.ts · `.../android/src/main/java/dev/matinzd/healthconnect/records/ReactExerciseSessionRecord.kt` · `.../permissions/HealthConnectPermissionDelegate.kt`
24. Historical route pain: #86 (2024-04, open) `readRecords('ExerciseSession')` threw `[Error: Consent required]` before the `CONSENT_REQUIRED` type existed; #127 (2024-08) empty routes from Google Fit/Samsung sources; #128 (2024-08) `SecurityException: Caller doesn't have android.permission.health.WRITE_EXERCISE_ROUTE` — maintainer: the permission "contract is necessary for reading too"; #210 (2025-03, open) `insertRecords` with a route → `[Error: Length is not valid]`. `[source-code]` https://github.com/matinzd/react-native-health-connect/issues/210
25. Incremental sync: `getChanges({ changesToken?, recordTypes?, dataOriginFilter? }): Promise<{ upsertionChanges: {record}[]; deletionChanges: {recordId}[]; nextChangesToken; changesTokenExpired; hasMore }>`; tokens valid ~30 days. Native: when `changesToken` is absent it calls `healthConnectClient.getChangesToken(...)` then `getChanges(token)` in the same call, so **the first call returns no records** (#243, open since 2025-12-18: "Can't get ExerciseSessions using the getChanges API" — reporter expected an initial snapshot). `[source-code]` https://raw.githubusercontent.com/matinzd/react-native-health-connect/main/android/src/main/java/dev/matinzd/healthconnect/HealthConnectManager.kt · `[official-doc]` https://matinzd.github.io/react-native-health-connect/docs/api/methods/getChanges
26. Error style: Kotlin `Promise.rejectWithException` maps exception classes to string codes — `PERMISSION_ERROR` (SecurityException), `SDK_VERSION_ERROR`, `IO_EXCEPTION`, `SERVICE_UNAVAILABLE`, `ARGUMENT_VALIDATION_ERROR`, `UNDERLYING_ERROR`, `INVALID_RECORD_TYPE`, `CLIENT_NOT_INITIALIZED`, `INVALID_TEMPERATURE/ENERGY/POWER/BLOOD_GLUCOSE_LEVEL/BLOOD_PRESSURE/MASS`, `AGGREGATION_NOT_SUPPORTED`, else `UNKNOWN_ERROR`. **`InvalidLength`, `InvalidVelocity` and `ExerciseRouteAccessDenied` are declared but missing from the mapping → surface as `UNKNOWN_ERROR`** (which is exactly the #210 route-save failure). JS-side `HealthConnectError extends Error` only wraps input validation in `insertRecords`. `[source-code]` https://raw.githubusercontent.com/matinzd/react-native-health-connect/main/android/src/main/java/dev/matinzd/healthconnect/utils/ExceptionsUtils.kt
27. Write-path bugs in current main: every `parseWriteRecord` hard-codes `startZoneOffset = null, endZoneOffset = null` (#268, 2026-08-04, open); `ReactExerciseSessionRecord.parseWriteRecord` reads **`laps` and `segments` from the JS key `"samples"`**, not from `laps`/`segments` as the TS type declares, so laps/segments passed from JS are silently dropped. `[source-code]` https://raw.githubusercontent.com/matinzd/react-native-health-connect/main/android/src/main/java/dev/matinzd/healthconnect/records/ReactExerciseSessionRecord.kt
28. `revokeAllPermissions()` "does not take effect until the app process restarts" (JSDoc, documented Health Connect limitation; returns `{ revoked, requiresRestart?, message? }`). `[source-code]` src/index.tsx
29. Keyword counts (issues, all/open): "new architecture" 76/18, expo 71/17, permission 76/14, anchor/getChanges/sync 29/16, crash 21/3, route 8/2, workout 2/1. `[source-code]` GitHub search API
30. Doc drift: the live docs page for `requestExerciseRoute` says `Promise<Location[]>` (matches source after 4.1.2 fix #263), but Context7's indexed copy still shows `Promise<ExerciseRoute>` with `requestExerciseRoute(recordId).then(({ route }) => ...)`. `[official-doc]` https://matinzd.github.io/react-native-health-connect/docs/api/methods/requestExerciseRoute · `[secondary]` Context7 `/matinzd/react-native-health-connect`

### 2.2 Native primitives every implementation ends up calling (for the from-scratch option)

iOS (Swift, Expo Modules `AsyncFunction` wrappers): `HKHealthStore.isHealthDataAvailable()`, `requestAuthorization(toShare:read:)`, `HKAnchoredObjectQuery(type: .workoutType(), predicate:, anchor:, limit:)` (+ `HKQueryAnchor` archived via `NSKeyedArchiver.archivedData(withRootObject:requiringSecureCoding:)` → base64), `HKQuery.predicateForObjects(from: workout)` + `HKAnchoredObjectQuery(type: HKSeriesType.workoutRoute(), …)` then `HKWorkoutRouteQuery(route:)` (batched `CLLocation` callback, `done` flag), `HKWorkoutBuilder` / `HKWorkout` + `HKWorkoutRouteBuilder.insertRouteData(_:)` + `finishRoute(with:metadata:)`, `HKObserverQuery` + `enableBackgroundDelivery`. Lesson from kingstinct 13.3.1: resume continuations on the main thread; never `try!`.

Android (Kotlin): `HealthConnectClient.getSdkStatus(context, providerPackageName)`, `HealthConnectClient.getOrCreate(context)`, `PermissionController.createRequestPermissionResultContract()` via an `ActivityResultLauncher` registered in the Activity (Expo: `ReactActivityLifecycleListener`), `readRecords(ReadRecordsRequest(ExerciseSessionRecord::class, TimeRangeFilter.between(...), pageSize, pageToken))`, `record.exerciseRouteResult` (`Data | NoData | ConsentRequired`) + `ExerciseRouteRequestContract()` for per-record consent, `getChangesToken(ChangesTokenRequest(recordTypes))` + `getChanges(token)`, `insertRecords(listOf(ExerciseSessionRecord(..., exerciseRoute = ExerciseRoute(route = listOf(ExerciseRoute.Location(time, latitude, longitude, horizontalAccuracy, verticalAccuracy, altitude))))))`. Manifest needs the `ACTION_SHOW_PERMISSIONS_RATIONALE` intent filter + Android 14 `VIEW_PERMISSION_USAGE` activity-alias (copy matinzd's plugin logic).

### 2.3 Minimal unified surface this audit argues for (sketch, not final)

```ts
// permissions: explicit, per-scope, per-platform-status
type Scope = 'workouts.read' | 'routes.read' | 'workouts.write' | 'routes.write'
getAvailability(): Promise<{ status: 'available' } | { status: 'unavailable'; reason: 'not-supported' | 'provider-missing' | 'provider-update-required' }>
requestPermissions(scopes: Scope[]): Promise<Record<Scope, 'granted' | 'denied' | 'undetermined' | 'unknown'>> // 'unknown' = iOS read status (Apple hides it)

// reading
listWorkouts(q: { from: Date; to: Date; activityTypes?: ActivityType[]; limit?: number; cursor?: string }): Promise<{ workouts: Workout[]; nextCursor?: string }>
getRoute(workoutId: string): Promise<{ status: 'data'; points: RoutePoint[] } | { status: 'none' } | { status: 'consent-required' }>
requestRouteConsent(workoutId: string): Promise<{ status: 'data'; points: RoutePoint[] } | { status: 'denied' }> // Android-only dialog; iOS resolves like getRoute

// sync
syncWorkouts(cursor?: string): Promise<{ upserted: Workout[]; deletedIds: string[]; nextCursor: string; cursorExpired: boolean; hasMore: boolean }>

// writing (one atomic call, library does Builder / ExerciseRoute plumbing)
saveWorkout(w: { activityType: ActivityType; start: Date; end: Date; distanceMeters?: number; energyKcal?: number; route?: RoutePoint[]; clientId?: string }): Promise<{ id: string }>

type RoutePoint = { timestamp: Date; latitude: number; longitude: number; altitudeMeters?: number; horizontalAccuracyMeters?: number; verticalAccuracyMeters?: number; speedMps?: number }
type ActivityType = 'running' | 'walking' | 'hiking' | 'cycling' | 'other'
class HealthError extends Error { code: 'unavailable' | 'not-authorized' | 'consent-required' | 'invalid-argument' | 'cursor-expired' | 'native' }
```

## 3. Design implications for a minimal-options unified API

**Expose**
- One `requestPermissions(scopes)` that returns *per-scope* status and never a single boolean (kingstinct's `Promise<boolean>` and AE's `initHealthKit` callback are the two most-complained-about shapes: AE "permission" 76 issues, #262/#394; kingstinct #352). Model iOS read-status opacity honestly with an `'unknown'` state instead of pretending (`getAuthStatus` read array always "SharingAuthorized").
- Route retrieval as an explicit tri-state (`data | none | consent-required`) mirroring Health Connect's `ExerciseRouteResult`, plus a separate `requestRouteConsent`. matinzd went from throwing `"Consent required"` (#86) to a `type` field; both kingstinct and AE have no equivalent because iOS has no per-record consent — the union still works on iOS (always `data`/`none`).
- Cursor-based sync with `deletedIds` and `cursorExpired`. kingstinct's `{workouts, deletedSamples, newAnchor}` and matinzd's `{upsertionChanges, deletionChanges, nextChangesToken, changesTokenExpired, hasMore}` are already isomorphic; normalise names, keep the token opaque, and **document that the first sync must be a `listWorkouts` backfill** (matinzd #243 confusion; react-native-nitro-health's README says the same).
- A single `saveWorkout({…, route})` that is atomic from the caller's view. kingstinct needs two calls (`saveWorkoutSample` then `proxy.saveWorkoutRoute`), AE cannot save routes at all, matinzd's single call is currently broken for routes (#210) and drops laps/segments (wrong key). Accept SI units only (meters, seconds, kcal, m/s). AE's miles-by-default `distance` is a standing trap.
- Typed error codes + a type guard (`isHealthError(e) && e.code === 'consent-required'`). This is consistent with AGENTS.md ("stable typed error code and type guard"; never expose raw native exceptions).

**Hide**
- `initialize()` (matinzd) — do lazy client creation internally; expose only `getAvailability()`.
- Platform identifiers (`HKWorkoutActivityTypeRunning` vs `ExerciseType.RUNNING` ints) behind a closed `ActivityType` union with an `other` bucket; keep the raw value under `platform.ios.activityTypeRaw` / `platform.android.exerciseType` for the rare consumer that needs it.
- Permission plumbing: Expo config plugin must do *all* of: Info.plist usage strings, `com.apple.developer.healthkit` entitlement, Android `<uses-permission android:name="android.permission.health.*">` derived from declared scopes, the rationale intent filter and the Android 14 activity-alias, and register the permission `ActivityResultLauncher` via an Expo `ReactActivityLifecycleListener`. matinzd's plugin does only the last two and leaves manifest permissions to `expo.android.permissions`, which is a recurring source of "permission denied" reports (#127/#128).
- Background delivery / observers in v1. They are the single largest complaint cluster (AE "background" 29 issues, kingstinct AppDelegate patching #372, sheet-flash #352) and require AppDelegate mutation on iOS; a foreground `syncWorkouts` on app-resume covers the product need.

**Normalise**
- Dates as `Date` (kingstinct) not ISO strings (AE, matinzd) on the JS surface; serialise as epoch ms at the bridge.
- `RoutePoint` = intersection of `CLLocation` and `ExerciseRoute.Location`: timestamp, lat, lon, altitude?, horizontal/vertical accuracy?, speed? (Health Connect has no course/speed on `Location`; HealthKit has both). Omit `course` from the common shape.
- Workout identity: HealthKit UUID vs Health Connect `metadata.id` → `id: string`; carry `source: { name, bundleId | packageName }` uniformly (`sourceRevision.source.bundleIdentifier` vs `metadata.dataOrigin`).
- Time zones: write the device offset explicitly on Android (matinzd writes `null`, #268) so exported workouts keep their local time.

**Packaging**
- Expo Modules API keeps the monorepo's "zero runtime dependency" rule (only `expo-modules-core` via the `expo` peer). Nitro would add `react-native-nitro-modules` as a required peer for every consumer and a codegen step (`nitrogen`); kingstinct's 2026 changelog (Xcode 26 workarounds, nitro 0.33/0.35 bumps, SIGSEGV continuation fix) shows the cost of riding that toolchain. This is a user decision (see §5).

## 4. Pitfalls / gotchas

1. **react-native-health cannot be built for the consumer app** (RN 0.86 / New Arch): `RCTCallableJSModules -setBridge:` removed (#443, open, unanswered). Its `@expo/config-plugins ^7.2.2` hard dep also fails `expo-doctor` on every SDK since 51 (#383). Treat as end-of-life.
2. **Leftover `expo-health-connect`** after upgrading to react-native-health-connect ≥4 fails the Android build with a duplicate `expo.modules.healthconnect.HealthConnectPackage` class.
3. **Health Connect route permissions are two-sided**: `WRITE_EXERCISE_ROUTE` must be both declared in the manifest *and* requested as `{accessType:'write', recordType:'ExerciseRoute'}`; reading another app's route needs `READ_EXERCISE_ROUTES` declared and, absent a blanket grant, per-record consent via `ExerciseRouteRequestContract` (`CONSENT_REQUIRED`). Exact blanket-vs-per-record semantics should be confirmed by the Health Connect dimension. `[unverified]`
4. **`getChanges` without a token returns nothing** — the library creates the token and drains in one call (#243). A sync layer that assumes "first call = full history" silently shows zero workouts.
5. **Health Connect change tokens expire (~30 days)**; must handle `changesTokenExpired` by re-backfilling.
6. **`revokeAllPermissions` takes effect only after process restart**; reads keep succeeding meanwhile — do not use it for an in-app "disconnect" toggle.
7. **Google Play declaration**: an app that reads/writes Health Connect without an approved Play Console declaration shows users an error dialog at link time (official). Budget review time before release; every new permission re-triggers review.
8. **HealthKit read authorization is opaque by design**: `authorizationStatus(for:)` only reflects sharing (write). A UI that waits for "read granted" will hang; use `getRequestStatusForAuthorization` (`shouldRequest | unnecessary`) to decide whether to prompt.
9. **kingstinct route reads leak memory per call (#370) and use `try!`** (crash, not rejection) in `getRouteLocations`; a "fetch route for each of N workouts" loop — exactly the fitness-app use case — can be jetsam-killed.
10. **HealthKit callbacks on background threads + JSI**: resuming Swift continuations off the main thread caused SIGSEGV in kingstinct ≤13.3.0. An Expo-Module implementation should hop to the main queue (or a dedicated serial queue) before resolving `Promise`s.
11. **Anchor serialisation**: kingstinct 14.0.1 had to switch to the non-deprecated `NSKeyedArchiver` API; use `archivedData(withRootObject:requiringSecureCoding: true)` / `unarchivedObject(ofClass: HKQueryAnchor.self, from:)` from day one; anchors are device/store-specific and must never be shared across devices.
12. **Units**: AE returns workout distance in **miles**; kingstinct returns `totalDistance` as `{quantity, unit:'meters'}`; matinzd returns `LengthResult {inMeters, inKilometers, inMiles, …}` on read but requires `{value, unit}` on write. Unit asymmetry read-vs-write is a classic foot-gun; keep one unit.
13. **Write-path silent drops in matinzd**: laps/segments parsed from the wrong key (`"samples"`), zone offsets forced `null` (#268), route write rejected with `UNKNOWN_ERROR` "Length is not valid" (#210). If wrapping, these must be patched upstream or worked around.
14. **Expo Go** is unsupported by every library here (native code); dev-client / prebuild is mandatory. Both active libraries say so in their READMEs.
15. **Docs drift** is systemic: kingstinct autodocs (`getWorkoutRoute`, options-object `saveWorkoutSample`, "default 20") and the Context7 copy of matinzd's `requestExerciseRoute` (`{route}`) both contradict current source. Generate docs from the TS types, or keep the surface small enough that the README is the doc.
16. **Platform bifurcation at import time**: matinzd throws `Platform not supported` from *every* call on iOS via a Proxy; kingstinct has no Android entry at all. A unified package must provide real no-op/`unavailable` behaviour on the other OS and on web/SSR resolution (AGENTS.md §2 resolution tests).

## 5. Open questions

**Needs a USER decision**
- Implementation substrate: **Expo Modules API (Swift/Kotlin, zero extra peers, matches AGENTS.md)** vs **Nitro Modules (faster sync calls, but adds `react-native-nitro-modules` peer + nitrogen codegen; kingstinct's track record shows toolchain churn)**.
- Wrap vs write: wrap `@kingstinct/react-native-healthkit` + `react-native-health-connect` behind a facade (fast, but inherits #370/#210/#268 and two different maintainers' release cadences), or write from scratch (more work, full control; can borrow MIT code/patterns from kingstinct's Swift and matinzd's Kotlin/plugin).
- Is **write** (saving the app's own workouts + routes) in v1, or read-only first?
- Android route consent UX: request `READ_EXERCISE_ROUTES` up front (single dialog) vs per-workout `requestRouteConsent` (more dialogs, less permission footprint). Affects Play declaration scope.
- Background delivery / observers: explicitly out of v1?
- Minimum OS: iOS 16 / Android API 26 (Health Connect min) vs API 28/34. Health Connect is built into Android 14+; on 8–13 users must install the app.

**Needs a hands-on device test**
- Does `@kingstinct/react-native-healthkit@14.0.2` + `react-native-nitro-modules@0.37.0` build and run on Expo SDK 57 / RN 0.86 / Xcode 26.6 / iPhone 17 simulator? (No in-repo evidence; example app is SDK 54; iOS 26.x regressions #340/#352/#359 exist.)
- Does `react-native-health-connect@4.1.3` on the Pixel_9a AVD (API level of the AVD to be checked; Health Connect built-in on 14+) read a route written by another app (Google Fit test data / Samsung Health not available on AVD — may need a second test app to write `ExerciseRoute`)?
- Reproduce #210 (route insert "Length is not valid") and #243 (`getChanges` first call) to confirm current behaviour on 4.1.3.
- Memory profile of an Expo-Module `HKWorkoutRouteQuery` loop over ~100 workouts (to avoid kingstinct #370).
- Simulator limits: HealthKit works in the iOS simulator but there is no GPS source; route tests need manually inserted `HKWorkoutRoute` data or a physical device.

**Needs more research (other dimensions)**
- Precise Health Connect semantics of `READ_EXERCISE_ROUTES` (blanket) vs `ExerciseRouteRequestContract` (per-record), and whether Play policy restricts route access categories. → Health Connect dimension.
- HealthKit: `HKWorkoutBuilder` vs legacy `HKWorkout(activityType:start:end:…)` initialiser availability/deprecation on iOS 17+/26, and `HKWorkoutRouteBuilder` device/metadata requirements. → HealthKit dimension.
- Expo SDK 57 autolinking behaviour for a package shipping both an RN TurboModule (`android/`) and an Expo module (`android-expo/`, `expo-module.config.json`) as matinzd does — relevant only if wrapping.
- Whether Expo Modules `AsyncFunction` on iOS runs on a background queue by default (affects the main-thread continuation concern in §4.10). → Expo Modules dimension.
