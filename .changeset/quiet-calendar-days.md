Round E stage E3 — pure date components. No native-picker peer (owner decision): everything below is clock-free, time-zone-free keyboard/pointer UI plus pure math, and the JavaScript Date object appears in no public signature — a Date is an instant whose civil reading shifts with the runtime time zone, so date state travels as the new plain `CalendarDate` (`{ year, month(1-12), day }`). Everything is additive; runtime dependencies stay at zero.

- **Pure calendar math** (new, root entry): `CalendarDate`/`CalendarMonth`/`CalendarWeekday`/`CalendarWeekStart` types plus `isCalendarLeapYear`, `daysInCalendarMonth`, `isValidCalendarDate` (a real-day guard — Feb 30 fails), `compareCalendarDates`/`isSameCalendarDate`/`isSameCalendarMonth`, `clampCalendarDate` (returns the same object when in range), `addCalendarDays`/`addCalendarMonths` (exact month/year boundary crossing via integer serial-day math, no Date), `calendarDayOfWeek` (0 = Sunday), ISO-key serialization `formatCalendarDateKey`/`parseCalendarDateKey` (strict zero-padded `"YYYY-MM-DD"`, the supported year space 1–9999), and `buildMonthGrid(year, month, weekStartsOn?)` → `MonthGrid` of 7-cell `MonthGridWeek` rows. The grid spans exactly the weeks the month needs (4–6 — no phantom sixth week); leading/trailing cells are real adjacent-month dates flagged `inMonth: false`. Every month of the year space lays out without throwing; the one documented caveat is the two edge months (January 0001, December 9999), whose padding cells name days outside 1–9999 (year 0 / 10000) — those padding dates fail `isValidCalendarDate` and are display data, not values to feed back into the calendar API. The module (`src/dates`) imports neither react nor react-native, so Node scripts and servers can load the math safely.
- **`MonthCalendar`** (new): a controlled month grid where the application owns every piece of date state — the displayed `month`, the selected `value`, and even `today` (an optional prop; the kit never reads the clock, so omitting it just means no today ring and no `aria-current="date"`). Header copy comes from a required `labels` prop rather than UiStrings, because weekday abbreviations and the month title are locale/calendar formatting decisions and the title changes every month — `labels.weekdays` is always a Sunday-first 7-tuple and `weekStartsOn` (`0 | 1`, default 1 = Monday) only reorders the columns. `renderDay` replaces a day's CONTENT only; the cell itself (gridcell/button semantics, focus, press) stays kit-owned so a consumer slot can never drop accessibility, and it is also called for `inMonth: false` padding cells so apps can render dimmed adjacent-month days. Padding cells are non-interactive; on the web they REMAIN in the accessibility tree as nameless `aria-disabled` gridcells with only their content hidden — hiding the cell itself would break screen-reader column arithmetic (exposed cell position determines the weekday column, the APG date-picker choice) — while on native, where each day is an independent button and no column mapping exists, padding is hidden from the tree entirely. `minDate`/`maxDate` disable out-of-range days — still focusable (`aria-disabled`), activation ignored. Default day accessible name is the locale-free ISO key; `getDayAccessibilityLabel` localizes it. Web semantics: `role="grid"` (named by the required `accessibilityLabel`) > `row` > `columnheader`/`gridcell`, `aria-selected` on in-month cells whenever selection is exposed (`onValueChange` or `value` present), and a roving-tabindex keyboard whose implemented surface is exactly: arrows ±1/±7 days clamped to the displayed month (movement that would leave the month is ignored), Home/End to the week's first/last in-month day, PageUp/PageDown raising `onMonthChange` with the previous/next month and restoring focus to the same day number (clamped in shorter months; a silent no-op at the edges of the year space instead of a throw), Enter/Space to select. Without `onValueChange` the grid is a static presentation (no focus, no keyboard, no press). Native: each in-month day is an honest button carrying the full date label and selected/disabled state (dual `accessibilityState` + `aria-*` notation, the Tabs convention); the weekday header row is hidden from the accessibility tree as noise. The component ships no built-in previous/next buttons — apps compose their own (Toolbar + Button) and share the `month` state with the keyboard path; on native only those app buttons call `onMonthChange`. Escape hatches: `dayStyle(ctx)` layered after the built-in token visuals (primarySoft selected wash, primary today ring drawn on an always-present transparent border so layout never shifts), `titleStyle`/`weekdayStyle`, per-day `${testID}-day-YYYY-MM-DD` testIDs.
- **`DateField`** (new): segmented year/month/day keyboard input, controlled `value: CalendarDate | null` ↔ `onValueChange`, order via `segmentOrder` (default ymd; a non-permutation is a runtime config error). The commit contract is deliberately narrow and tested verbatim: typing keeps LOCAL per-segment drafts and commits only the moment all three are complete (year 4 digits, month/day 2); the commit clamps month → 1-12, day → the real length of that month (Feb 31 → 28/29), result → `minDate`/`maxDate`, and calls `onValueChange` only when the result differs from `value`; emptying all three segments commits `null` (partially empty commits nothing); blur zero-pads a single-digit month/day but NEVER pads or century-guesses a short year (it stays an uncommitted draft), and blur with complete drafts drops them so the display snaps back to the controlled value; a parent `value` change discards drafts. Numeric keyboard on both platforms, unambiguous first digits complete early ("9" → "09" for months, "4"-"9" for days) with auto-advance, Backspace on an empty segment flows back, and web ArrowUp/ArrowDown steps within the segment's own range (day max uses the real month length when year+month are known) — an empty segment does not respond, because the kit is clock-free and has no "today" to seed from, and an incomplete year draft ("26") is equally inert: stepping never pads or century-guesses a short year, mirroring the blur contract. Semantics: web `role="group"` wired to the label plus per-segment `role="spinbutton"` with `aria-valuemin/max/now` — the day segment's `aria-valuemax` is computed with the same rule as the step ceiling (the real month length once year+month are known, 31 only while unknown) — and per-segment `aria-describedby`/`aria-errormessage` alongside `aria-invalid`, because ARIA only honors `aria-errormessage` on the invalid element itself (the segments are the focusable elements, matching TextField's wiring); native three inputs labeled "field label, segment name". Segment names come from three NEW `UiStrings` keys `dateFieldYear`/`dateFieldMonth`/`dateFieldDay` (en "Year"/"Month"/"Day", ko "년"/"월"/"일") — hand-assembled UiStrings bundles must add them, the documented complete-object evolution path — overridable per field via `segmentLabels`. `label`/`error`/`helperText` wiring matches TextField, and the `nativeID`/`aria-*` passthrough props make it compatible with the FormField render-prop contract. TimeField was considered and deliberately deferred out of this stage's budget.
- Type contracts: `CalendarDate` is a closed flat shape (a `Date`, a key string, or an excess property is a compile error on both components' `value`), the `renderDay`/`getDayAccessibilityLabel`/`dayStyle` context is fully readonly, `weekStartsOn` admits only `0 | 1`, `labels.weekdays` is enforced as a 7-tuple, and `MonthGridWeek["length"]` is literally `7`.
